在企业数字化中，"知识治理"和"数据治理"经常被并列提及，甚至混用。但二者治理的对象、依托的标准和落地路径并不相同，理清它们，是避免"两套治理互相打架"的前提。

## 一、治理对象不同

| 维度 | 知识治理 | 数据治理 |
|---|---|---|
| 治理对象 | 知识（经验、规则、方法、隐性知识） | 数据（结构化/非结构化数据资产） |
| 核心资产 | 知识资产、术语、本体 | 数据资产、数据标准、血缘、质量 |
| 典型产出 | 知识分类分级、知识地图、本体、经验库 | 数据标准、元数据、数据质量规则、血缘 |
| 主要载体 | 知识库、文档、案例库 | 数据中台、湖仓、catalog |
| 成熟度参考 | GB/T 41304.5、知识管理成熟度模型 | DCMM（GB/T 36073）、DAMA-DMBOK |

> 简单说：数据治理管"**数**"，知识治理管"**知**"。数据是原料，知识是把原料提炼出的经验与规则。
{: .prompt-tip }

## 二、依托的标准体系不同

- **数据治理侧**：以 DCMM（GB/T 36073，能力成熟度）与 DAMA-DMBOK（知识体系）为代表，方法论相对成熟。
- **知识治理侧**：以 GB/T 41304.5-2025、GB/T 23703《知识管理 框架》及信通院能力成熟度模型为代表，体系相对年轻。

对比如前文[《知识治理成熟度模型》](/posts/knowledge-maturity-model/)所述，知识治理更强调"评估域 + 能力域"的双视角，而数据治理更强调标准、质量与血缘的工程化落地。

## 三、二者的交汇与边界

现实中二者并非割裂，而是相互依赖：

- **知识依赖数据**：知识元数据、术语标准都依托结构化数据与元数据管理。
- **数据需要知识**：数据语义解释、业务规则、口径定义本质上是"知识"，缺乏知识约束的数据治理容易沦为形式。
- **交汇区**：主数据、元数据管理、业务术语库——通常是双方共建的领域。

```
     数据治理                        知识治理
   (标准/质量/血缘)  ───交汇───  (术语/本体/经验)
            │                        │
            └── 共同底座：元数据 + 权限 + 考核 ──┘
```

## 四、融合落地的建议

1. **统一元数据底座**：知识与数据共享一套元数据规范与权限体系。
2. **术语库共建**：业务术语既服务数据口径，也服务知识表达，是天然的结合点。
3. **治理组织一体化**：成立含数据与知识双视角的治理委员会，避免职责真空。
4. **成熟度联合评估**：以数据治理成熟度为底座，叠加知识治理要素，形成组织整体知识资产能力画像。

> 融合的目标不是"合成一个体系"，而是让数据可被理解、让知识有据可依——前者靠治理，后者靠固化。
{: .prompt-info }

## 小结

知识治理与数据治理是数字化的一体两面：数据治理保障"数据可信可用"，知识治理保障"知识可传承可复用"。在标准上各有体系，在落地中应统一底座、共建术语库，在组织上避免两条线互相割裂。这与[房屋模型](/posts/knowledge-governance-housing/)中"政策标准"与"技术平台"两根支柱高度呼应。
