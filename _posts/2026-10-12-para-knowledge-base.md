知识库最怕的不是内容少，而是"建了之后慢慢烂掉"。我采用 **PARA + 数字前缀**的组合：PARA 提供流转逻辑，数字前缀固定排序，让库在几年后依然可控。

> 本文以通用结构为示例，库名与目录名均为通用占位。
{: .prompt-info }

## 一、PARA：按"可行动性"组织，而非按主题

PARA 由 Tiago Forte 提出，按信息的**可行动性**分四类：

| 类别 | 含义 | 例子 | 特点 |
|---|---|---|---|
| **P**rojects（项目） | 有明确目标和截止时间 | 一个产品上线、一次搬家 | 有终点的，优先推进 |
| **A**reas（领域） | 需长期维护的责任 | 健康、财务、职业 | 无终点的，长期养护 |
| **R**esources（资源） | 将来可能用上的主题材料 | 笔记、参考、模板 | 主题性的，供参考 |
| **A**rchives（归档） | 已完成/不再活跃 | 过往项目、旧笔记 | 冻结的，定期清理 |

> 核心不是分类本身，而是"**先看它现在能不能推动某件事**"：能推动的放 Project/Area，暂不能的放 Resource/Archive。
{: .prompt-tip }

## 二、加上数字前缀，固定排序

在 PARA 之外叠加数字前缀，让目录自带阅读顺序（0 排在最前）：

```
00-Daily        每日笔记
00-Inbox        收件箱（未分类）
01-I.O.         重要项目/长期命题
10-Projects     项目（进行中）
20-Areas        领域（长期）
30-Resources    资源（参考、阅读、标准）
31-Library      书库/阅读输出
40-Archive      归档
50-People       人物
90-Review       复盘
99-Assets       附件资源
99-Templates    模板
```

好处：文件管理器按名称排序即符合逻辑；`00-` 开头让 Daily/Inbox 永远置顶。

## 三、模板与自动化

目录有了，接下来让"写"这件事更省力：

- **Templater 绑定文件夹**：在 `00-Daily/` 新建文件自动套用日记模板；在会议目录自动套用会议模板。
- **QuickAdd 快速捕获**：`Ctrl+Shift+Q` 把闪现的想法直接落到 Inbox，不打断当前工作流。
- **元数据驱动**：在 front matter 维护 `date/project/status/tags`，为 Dataview 自动生成仪表盘打好基础。

> 让常用动作"一键可达"，比任何整理技巧都更能延长知识库的生命。
{: .prompt-tip }

## 四、让知识库"活"起来的习惯

1. **Inbox 定期清空**：周末把 `00-Inbox` 归类到 Projects/Areas/Resources，不积压。
2. **项目完成即归档**：完成的 Project 转入 Archive，避免"僵尸项目"堆积。
3. **链接而非堆放**：跨目录用 `[[双向链接]]` 关联，主题聚合交给链接而非文件夹。
4. **定期复盘**：利用 `90-Review` 周期性总结，输出到 `31-Library`。

## 五、配套的版本与检索

目录与模板解决"放得下"，还需要"找得回、丢不了"：

- **Dataview** 把笔记库当数据库查（清单、仪表盘）。
- **Smart Connections / Copilot** 提供语义检索与 AI 问答（见[《AI 增强的笔记工作流》](/posts/ai-note-workflow/)）。
- **Obsidian Git** 提供版本控制与私有备份（见[《用 Git 管理笔记》](/posts/git-note-workflow/)）。

## 小结

一个能长期生长的知识库，靠的不是一次性完美设计，而是**清晰的流转逻辑 + 低摩擦的自动化 + 定期的维护习惯**。PARA 定骨架、数字前缀定顺序、模板与插件定效率、Git 定保障——四者叠加，库就会越用越顺，而不是越用越乱。
